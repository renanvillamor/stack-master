# StackMaster APK release

Ships a new Android release: version bump → **release build** → GitHub Release with `StackMaster.apk` attached.
The in-app Share dialog links to `releases/latest/download/StackMaster.apk`, so the asset name must be exactly `StackMaster.apk` and the new release must be marked Latest.

Arguments (`$ARGUMENTS`): optional new version (`X.Y.Z`) followed by optional release-notes text. If no version is given, propose the next minor version (e.g. 1.1.0 → 1.2.0) and confirm it with the user. If no notes are given, draft them from the commits since the previous tag.

Run from the repo root `D:\Projects\StackMaster`. `gh` may not be on PATH in this shell — use `"/c/Program Files/GitHub CLI/gh.exe"` (Bash) if `gh` isn't found. Prefer the **Bash** tool for every step: PowerShell 5.1 mangles quotes in native-exe args and adds a UTF-8 BOM when writing files.

## 1. Preflight — stop and report if any check fails

```bash
git status --porcelain            # must be empty (commit or stash first, ask the user)
git branch --show-current         # expected: master
git pull --ff-only
"/c/Program Files/GitHub CLI/gh.exe" auth status          # if logged out: ask user to run  ! "C:\Program Files\GitHub CLI\gh.exe" auth login
"/c/Program Files/GitHub CLI/gh.exe" release list -R renanvillamor/stack-master   # current latest tag (format: v1.0, v1.1, ...)
test -f .env && test -f android/app/debug.keystore && echo ok
```

- `.env` holds the Supabase keys that get baked into the bundle — without it Live Sync breaks in the APK.
- `android/app/debug.keystore` signs release builds (see `android/app/build.gradle` → `signingConfigs`). Every published APK so far is signed with **this** keystore; if it's missing or `android/` was regenerated by `expo prebuild --clean`, a new keystore means the APK **won't install over the existing app** (users would have to uninstall, losing data). Stop and tell the user rather than shipping a differently-signed APK.

## 2. Bump the version (both places — `android/` is gitignored)

Read current values first, then bump:

- `app.json` → `expo.version` = `"X.Y.Z"` and `expo.android.versionCode` = previous + 1
- `android/app/build.gradle` → `defaultConfig { versionCode N; versionName "X.Y.Z" }` — same numbers

`versionCode` must strictly increase or Android refuses the update. Use the Edit tool (no BOM). The Settings "StackMaster vX.Y.Z" tile reads `Constants.expoConfig.version`, so no code change is needed there.

## 3. Generate the release build

```bash
cd android && ./gradlew assembleRelease --console=plain > "<scratchpad>/build.log" 2>&1; echo "exit $?"; tail -5 "<scratchpad>/build.log"
```

Run in the background (`run_in_background: true`) — it takes ~3+ minutes. On failure, show the relevant error lines from the log and stop.

Then verify and name the artifact:

```bash
cd android/app/build/outputs/apk/release
grep -oE '"version(Code|Name)": ?[^,]+' output-metadata.json   # must match the bump from step 2
cp app-release.apk StackMaster.apk
ls -l StackMaster.apk
```

## 4. Commit and push the version bump

```bash
git add app.json
git commit -m "Bump version to X.Y.Z (versionCode N)"   # end with the Co-Authored-By trailer from the session's attribution instructions
git push
```

## 5. Confirm, then publish the GitHub Release

Publishing is outward-facing (everyone's Share QR immediately points at it). Show the user the tag, title, and notes and get a go-ahead before running this.

Write the notes to a file in the scratchpad (never pass multi-line notes inline), using this shape:

```markdown
## What's new
- ...

## Install
Download `StackMaster.apk` below on your Android phone and open it. You may need to allow "Install unknown apps" for your browser. Installs over the previous version without losing data.
```

```bash
"/c/Program Files/GitHub CLI/gh.exe" release create vX.Y \
  android/app/build/outputs/apk/release/StackMaster.apk \
  -R renanvillamor/stack-master --target master \
  --title "Stack Master vX.Y" --notes-file "<scratchpad>/notes.md" --latest
```

Tag/title convention: `vMAJOR.MINOR` (drop a `.0` patch, e.g. 1.2.0 → `v1.2`; keep a non-zero patch, e.g. `v1.2.1`).

## 6. Verify

```bash
"/c/Program Files/GitHub CLI/gh.exe" release list -R renanvillamor/stack-master   # new release shows "Latest"
curl -sI https://github.com/renanvillamor/stack-master/releases/latest/download/StackMaster.apk | grep -i '^location'   # must point at /download/vX.Y/StackMaster.apk
```

Report the release URL, the version/versionCode, and the verified redirect. Note that the download count in the Share dialog lags ~10 minutes behind real downloads.
